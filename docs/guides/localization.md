# 界面语言与翻译贡献

验证工作台支持简体中文与英语。通过页面右上角的语言菜单切换，偏好自动记忆；首次访问根据浏览器语言选择，不支持的语言回退英语。

也可以用 `?lang=en` 或 `?lang=zh-CN` 分享指定语言的页面。切换在当前页面即时完成，复用已加载的运行与架构数据，无需重新导航或读取报告。选中的运行、当前视图、地图视角和筛选状态保留；日期按对应语言及浏览器时区显示，运行时间戳保持不变。

## 翻译范围

中英文覆盖总览、历史、检查操作、覆盖率、架构地图、内置诊断和问题处理入口。源码、原始日志、堆栈、检查标识与用户配置的说明保持原文。CLI 和机器报告的稳定契约不随界面语言改变。

## 自动化流程

翻译资源位于 `apps/web/locales/`，简体中文资源定义消息键。英语及其他语言必须提供同一组键；动态消息保留 `{count}` 等占位符。

```bash
pnpm i18n:check        # 检查资源完整性、额外键、占位符及已注册界面消息
pnpm i18n:add fr       # 创建法语资源草稿，不覆盖已有资源
```

补齐译文后再次运行检查并提交 PR。完整资源会自动出现在语言菜单中；未完成草稿不展示。`Translation contracts` 工作流在相关 PR 和主分支提交中自动检查资源，无需翻译服务密钥。

机器翻译或社区翻译平台可以读写同一组 JSON 资源，生成候选译文并提交 PR。自动生成与人工审核相结合：维护者确认术语、占位符、操作含义和布局后合并。当前流程负责生成草稿、校验资源与自动接入完整语言，不会在后台调用收费模型或自动发布未经审核的译文。

新增界面消息时，使用 `t('消息键')`；需要参数时使用 `tfmt('含 {count} 的消息键', { count })`，并同步更新所有正式语言资源。不要将日志、源码或用户输入送入翻译函数。
