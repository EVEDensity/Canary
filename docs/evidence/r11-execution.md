日期：2026-09-26。Windows、Node `v24.18.0`、pnpm `10.15.0`、Microsoft Edge 无头模式。进入 R11 时的最近提交为 `bd8262a`；R10 工作树改动尚未提交，本阶段在其上实现。

## 交付与观察

- 首页加入“从架构进入问题现场”入口，显示本次运行的模块、文件和符号数量；同页地图提供二维结构与可切换的三维分层视角。
- 层级树、面包屑、搜索、聚焦、折叠、关系过滤与一跳上下游可用。二维限制为每层最多 48 个节点、24 条同屏依赖线；其他节点仍可通过树和搜索访问。视角与过滤按运行保存在浏览器会话中。
- 节点详情显示路径、采集时行号、基于结构的职责摘要、Git 变更、上下游、未确定关系及可验证的检查关联。源码片段须与封存 SHA-256 匹配，旧文件可尝试从对应 Git 提交读取；无法复核时拒绝展示。
- 页面仅细分 JS/TS 的函数与类；其他语言当前在页面保留目录/文件层级。三维展示为交互布局，不是运行时调用图。

## 验证

`pnpm build` 与 `pnpm check` 通过，包含全仓 typecheck、测试、lint 和格式检查。Web 新增脚本语法/控件测试、脏工作树源码拒绝测试，以及子运行覆盖哈希与父检查关联测试；Web 共 37 项通过，CLI 共 137 项通过。篡改子运行证据后，结构接口返回 409，未继续显示检查关联。

在 Canary 自身仓库执行 `canary run --port 4318 --no-open --base HEAD --config canary.project.json`，封存运行 `run_3c200659-7061-4349-b661-8e93d8a81930`，得到 1,349 个节点、4,800 条已确认关系。该次运行 6 项检查中 5 项通过，`workspace.test` 因四个端到端测试超过 Vitest 默认 5 秒而失败；将 CLI 与 Web 的真实进程测试预算设为 20 秒后，独立 CLI 测试和全仓 `pnpm check` 均通过。该历史运行保持失败状态，未改写证据。随后执行 `canary run --ci --base HEAD --config canary.project.json`，新运行 `run_89eb461b-11ec-46d1-94f4-b1ae31f84c1c` 的 6 项检查全部通过，退出码为 0，封存结构为 1,351 个节点。

本机 Edge 无头浏览器分别对失败历史运行和最新通过运行执行真实页面交互：首页显示 22 个应用/包；二维首层绘制 19 个节点，三维形成 3 个分层卡片；搜索 `architecture-map.ts` 可进入 `Canary/apps/web/src`，上下游模式收敛为 5 个节点与 4 条连线。旧运行后改动的该文件源码被拒绝，新运行中哈希一致的文件可读到片段；刷新页面后所选文件、二维视角与上下游过滤得到恢复。浏览器真实键盘输入右方向键进入 `icons.ts` 层、左方向键返回 `src` 层。两次浏览器验收均未报告脚本异常。结果和截图位于本机被 Git 忽略的 `.canary/logs/r11-browser-dirty.json`、`r11-map-dirty.png`、`r11-browser.json`、`r11-map.png` 和 `r11-map-3d.png`。
