# 统一工作台验收记录

## 改动

项目检查与 Agent 页面共用 `workspace-ui.ts`，新增紧凑历史和详情 API。项目详情关联同仓库、manifest 匹配的 Agent 子运行覆盖率。历史按摘要读取，选中后校验，轨迹按需加载；旧项目列表先筛选项目记录，避免加载无关 Agent 轨迹。

## 实际验证

- Web 测试 20 项通过，包含损坏子证据、重试不继承覆盖率、脱敏、跨源拒绝及历史按需读取。
- R5 会话测试 5 项通过，覆盖进度、重跑、谱系、关闭与项目隔离。
- 全局启动 `canary run --port 4318 --no-open`，运行 `run_780ede62-f129-4f1e-80eb-ae52b116a66c` 的 build、typecheck、lint、format、test、Agent 六项全部通过。后续断言文字回退的小修复重新通过 Web 构建和 20 项测试。
- 浏览器实际查看桌面总览、覆盖率、Agent 用例、断言、按需轨迹；390 像素视口下文档宽度 375 像素，无横向溢出，验收后恢复默认视口。
- 实际 API 确认完整历史项目运行行覆盖率 98.73%、分支 77.08%，来源为关联 Agent；仅命令重试运行的覆盖率来源为空。项目比较将缺席检查标记为未运行。

调试期间旧页面仍请求完整历史，出现高内存和响应阻塞。已修复旧项目列表的加载路径、关闭旧临时服务并重新启动。浏览器控制连接中断后恢复，完成上述浏览器检查。中途停止的运行保留其原始记录，不覆盖成通过。

## 限制

本次工作不增加整个仓库的测试覆盖率采集。现有数值只对应 Agent 配置范围，近似及不可用源码映射保留明确标记。R6 的平台与 Pi 阻塞状态不因 UI 验收而改变。
