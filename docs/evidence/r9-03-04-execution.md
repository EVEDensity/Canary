# R9-03 / R9-04 比较可信度与诊断路径

日期：2026-09-25；环境：Windows 11、Node 24.18.0、pnpm 10.15.0。R9-02 的真实故障/修复配对数据集尚未建立；本次验证使用固定单元 fixture 和项目中已有的真实历史 artifact，不能推断跨项目收益。

## R9-03：比较结果如何解读

`/api/compare` 保留原比较结果，并增加独立 `assessment`。它显示基线、候选与配对样本数，改善、回归、未变化和缺席数量，以及评估方法、比较范围和不确定性。配对项少于 5 时显示“证据不足”；**5 是探索性展示门槛，不是显著性检验或发布标准**。不同项目检查并非独立同分布样本，因此不绘制虚假的置信区间。

Agent 比较要求相同的用例输入、断言和数据集身份，并检查任务结果的确定性断言是否在两次运行中实际执行。单独的 `output.exists`、输出形状或工具调用不能证明任务完成。当前可形成确定性观察的结果断言是 `state.equals` 与 `state.contains`；`output.predicate` 虽然是确定性断言，但函数实现和闭包尚未固化到 artifact，因此仍显示“证据不足”。只要配对用例包含 `judge.score`，正向收益判断同样为“证据不足”：当前没有绑定模型/评分器、rubric 与人工标签的真实校准集，不能用模型评分补足任务正确性证据。模型评分仍可作为原始用例观察，但不用于可信收益结论。

项目比较先校验两份封存证据和检查计划。来自同一谱系的重跑子集只做**所选检查**比较，并明确“不能代表全项目”。缺失配对项、计划变化、运行未结束、基线晚于候选、样本过少均展示具体原因；已观测到的回归单独突出，不被改善数量抵消。页面文字始终把计数称为观察变化，不宣称因果收益或自动发布准入。

## R9-04：一次问题的操作顺序

页面的“改进建议”针对每个问题连续展示：**失败 → 分类 → 错误证据 → 复现 → 修复后重跑 → 前后比较**。从首页异常卡进入详情抽屉，可查看原始检查、脱敏日志、工作目录、命令参数、断言与文件行号，再跳转完整处理流程。操作按钮使用现有写入令牌；只读会话禁用重跑。

项目检查通过 `retryOf`、父 manifest 哈希、相同检查计划及必需前置项验证关联结果。Agent 用例通过 `replayOf`、父 manifest 哈希、相同输入/断言/重复轮次和封存证据验证；损坏或半写入的重放不会把原问题标为通过。原失败 artifact 保留，重跑生成独立 runId。前后比较可从问题卡直接打开，并显示子集范围与缺口。
