# H：受控硬进化

> 全部待实施。H 系列未验收前，不开放自动源码写入。权限开关本身不是隔离机制。

<a id="h-01"></a>

## H-01 · 外置策略、最小权限与真实隔离

- **依据/范围**：当前 worker 继承 process.env，config/predicate 在控制进程执行，HTTP/MCP 没有统一隔离；MemoryStateStore 不能回退外界。覆盖 runner/environment/adapters 及受信执行服务。
- **交付**：威胁模型、按平台可验证的文件/网络/进程隔离；环境变量 allowlist；独立只读策略/评估数据；授权/预算账本；受控工具代理；沙箱能力缺失时 fail closed。
- **验收**：逐项执行 POL-01/02/03/05/06/07/09；绝对路径、路径穿越、链接越界、未授权网络/工具、环境密钥、恶意 config/predicate、后台子进程、并发预算绕过均有拒绝证据。必须说明哪些进程在沙箱内，哪些在外。
- **依赖/回滚**：F-05 执行端口；威胁建模可提前。禁用隔离后只能保留受信人工建议模式，不能退回无隔离自动写。
- **排除**：将 worktree/Node 子进程/MCP 权限提示等同于 OS 安全边界。

<a id="h-02"></a>

## H-02 · 有边界的源码候选与独立验证

- **范围**：新增候选工作区/变更清单服务，使用受控执行器运行候选；不让提案进程写原项目、保护测试、策略和审批记录。
- **交付**：仓库身份、允许路径和动作；补丁/完整 diff/内容哈希；依赖/构建脚本变更的专门策略；独立测试、质量门禁、审计证据。
- **验收**：授权文件中的已知缺陷可形成有效候选；修改测试/阈值、扩大文件范围、访问隐藏集、伪造报告都拒绝；失败/不确定不进入应用队列；用真实所有权/fork 授权而非开源标签判定。
- **依赖/回滚**：H-01、Q-01/02/03/04；候选可废弃，但不删除原项目或历史证据。
- **排除**：自动修改 Canary 的控制器/策略本身、自动提升授权、自动 push/部署。

<a id="h-03"></a>

## H-03 · 精确应用、模式切换、撤销与回滚

- **范围**：新增受信应用器和审批记录；soft/hard、manual/auto_within_policy 两维开关；默认关闭自动硬写。
- **交付**：校验被批准的候选哈希、实验结论、有效授权、策略版本和当前基线；冲突检测、原子应用或安全恢复；撤销阻断排队任务；独立版本回退与事件记录。
- **验收**：hard+auto 在授权内可自动完成本地修复；soft 不能写源码；过期/撤销/基线漂移/用户未提交修改冲突/验证后换包均阻断；崩溃恢复不重复应用；不开 Git 远端权限就不能 push；外界副作用不能声称已回退。
- **依赖/回滚**：H-02、F-04；先人工批准链验证，再开放限额自动应用。撤销开关不隐式覆盖用户当前文件。
- **排除**：自动提交/远端操作/部署权限的捆绑授予，无法验证边界时继续运行。
