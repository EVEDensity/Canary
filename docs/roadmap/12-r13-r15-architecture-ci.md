## R13：有证据的架构分析

- 从已解析的静态导入与包依赖识别循环，保留成员、边和源码路径。
- 用户在 `canary.architecture.json` 显式声明禁止的层间依赖；没有规则时不猜测架构好坏。
- 展示扇入、扇出等耦合观察及未知关系；观察不等于故障。
- 分析与对应源码结构一起封存，页面和 CLI 读取同一份结果。

验收：真实 fixture 的循环和禁止依赖可定位；未知、运行时及推断边不构成静态违规证明。

## R14：可追溯的变更影响

- 固定 Git 基线 commit，展示新增、修改、删除、重命名。
- 沿已解析的静态依赖反向寻找消费者，每个受影响节点保留最短解释路径。
- 删除、重命名、动态关系、解析缺失及全局配置变更明确降低可判定范围。
- 不把潜在影响称为已发生的错误；旧运行始终读取旧分析。

验收：共享模块的改变可追踪到其消费者；影响分析有未知原因和保守回退依据。

## R15：可解释的增量 CI

- 默认全量；显式 `--affected --base <ref>` 才请求增量检查。
- 检查可声明 `impact.paths` 或 `impact.always`，未声明范围的检查照常运行。
- 选择范围包含受影响消费者和检查前置依赖；缺少可信范围时执行全量。
- 封存原始计划、执行/省略理由及实际检查结果；省略不计为通过。
- 提供 CLI 预览和页面计划入口，无模型调用，无自动源码修复。

验收：真实 CLI 比较全量与增量，确认该执行的检查未被漏选；全局配置、删除及未知输入触发回退；失败仍保留非零退出码。
