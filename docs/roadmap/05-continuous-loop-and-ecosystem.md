# L：持续自循环、观察与生态

> 全部待实施。本阶段依赖前面的可信评估和安全边界，不可从“定时唤醒模型”直接跳到自动进化。

<a id="l-01"></a>

## L-01 · 有限、可恢复的持续控制器

- **范围**：新增独立 loop controller，不把无限 while loop 塞进 Runner。显式 executor 可以是用户授权的宿主会话、API 或本地模型。
- **交付**：持久状态机、触发去重/冷却、项目租约锁、幂等试验/应用、累计预算、停止/等待/重试策略、人工接管；授权和预算由控制器持有。
- **验收**：多轮软进化可观察；固定轮数、费用、时间和无收益阈值能停止；宿主消失进入等待；故障注入覆盖评估中/审批中/应用前后恢复；重复事件不会重复付费或应用；撤销可阻断后续动作。
- **依赖/回滚**：S-04、H-01；自动源码应用另需 H-03。停用后台执行不删除活动版本，是否回滚另按策略。
- **排除**：安装即自启动、无限预算、自动寻找未授权模型凭证。

<a id="l-02"></a>

## L-02 · 长期质量观察与可审计控制面

- **范围**：Web/应用服务/证据存储；兼顾无 UI 的 CLI 查看和人工批准。
- **交付**：基线/候选/活动版本谱系、加载经验、硬门禁与语义指标分栏、预算/授权/停止原因、受保护审批/撤销/回滚；固定锚点、漂移检测、保留集轮换与泄漏审计。
- **验收**：未知指标不画成零；长期多次小退化可在锚点对比中发现；刷新/重启可追溯决策；只读用户不能触发写操作；审批有防重复和版本绑定；实际结果与 Agent 自述分开展示。
- **依赖/回滚**：L-01、F-02/04、Q-04；UI 不得拥有比受信后端更大的授权，旧证据仍可读取。
- **排除**：保证所有任务长期单调进步、自动线上业务试验或生产部署。

<a id="l-03"></a>

## L-03 · 发布兼容与可选外部观测

- **范围**：分发/升级流程、跨平台验证、按需 OTel/Phoenix/Langfuse exporter；exporter 与本地存储解耦。
- **交付**：明确支持的平台/Node/包管理器/宿主/协议版本；安装、升级、卸载、离线失败体验；用户主动启用的脱敏导出、限流与失败隔离。
- **验收**：在声明平台的干净环境从目标项目启动；安装根和项目根不混淆；不启用 exporter 时无外发；外部服务宕机不阻止本地评估；导出不得泄露原始凭证/保留集。
- **依赖/回滚**：F-01/02/04/05；安装验证可早做，外部观测不是自循环前置条件。可关闭 exporter，不改变原有运行证据。
- **排除**：本次发布 npm/二进制、将云服务作为基础功能硬依赖。
