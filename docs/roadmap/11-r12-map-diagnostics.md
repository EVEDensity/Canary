# R12：覆盖、分支与失败的架构地图联动

R12 在 R10 封存结构和 R11 地图上读取同一运行的覆盖、分支与失败证据。操作见[地图指南](../guides/architecture-map.md)，本机验收见[R12 证据](../evidence/r12-execution.md)。

| 需求                 | 实现与可信边界                                                                                                                                        |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 文件、函数、行、分支 | 文件使用原覆盖报告分母；函数与类只有在封存的 coverage manifest 提供位置与 ID 时计算局部分母；无局部分母显示未知。各子运行保持独立来源，不合并百分比。 |
| 指标跳转             | 总览与覆盖分析的指标可进入地图；按测量来源与指标聚焦最薄弱的已测文件。文件明细可直接定位对应文件。                                                    |
| 未覆盖分支           | 使用采集器记录的分支类型、索引、源码行列与隐式 else 标记描述缺失路径；源码片段经封存哈希核对后高亮。近似映射持续标记为近似。                          |
| 失败定位             | 从有界、脱敏的检查输出与断言摘要中识别 Node/Python 堆栈，匹配项目内文件和函数，再核对封存源码哈希与行号。没有定位证据时显示未知。                     |
| 三种颜色             | 覆盖、失败、变更各有固定图例。橙色是验证缺口，红色是本次失败，紫色是同版历史失败，绿色在失败模式表示关联重跑已验证。                                  |
| 历史与恢复           | 原运行的失败在关联重跑验证后保留为“修复后已验证”；最近三个同项目、同文件哈希的失败运行可显示历史标记。不同源码版本不覆盖当前地图。                    |

边界：未覆盖不能推断代码有错；堆栈的路径与行号不能证明命令执行时每个字节的版本，页面仍保留原始检查证据。外部黑盒、未采集、哈希不一致、无法恢复的源码和无分母符号保持未知。当前细粒度函数覆盖仍以 JS/TS 封存 manifest 为准。
