# S：宿主接入与软进化

> 全部 S-01/S-03/S-04 已实施。S-02（MCP Server）仍为待实施。默认人工触发；安装不自动常驻，不自动花费 Token。

<a id="s-01"></a>

## S-01 · Skill + CLI 的最小宿主闭环

- **依据/范围**：当前已有运行/建议 CLI，但没有经过实测的 Canary 宿主 Skill 工作流。新增一个明确宿主版本的集成说明/Skill 和 CLI 结构化输出；不宣称全宿主通用 `/canary`。
- **交付**：发现目标项目→运行评估→读取有界证据→宿主提出结构化建议→返回 Canary 验证；明确指令与不可信 Trace 分隔，限制上下文量。
- **验收**：在真实宿主执行一次成功和一次拒绝流程；无宿主模型时 CLI 仍可用；无私有凭证读取；建议有 run/case 引用，不能伪造已批准；宿主关闭后不继续假装运行。
- **依赖/回滚**：F-01、Q-01/02/03；可卸载 Skill，不影响 CLI 和已有产物。
- **排除**：安全沙箱承诺、后台无限任务、把宿主自评作为独立质量证明。

<a id="s-02"></a>

## S-02 · 可选 Canary MCP Server 与协议兼容矩阵

- **依据/范围**：现有 adapters 是外部 MCP 客户端，不能据此宣称已有 Canary 服务端。现有 stdio/HTTP 演示路径也不能代表完整协议兼容。
- **交付**：仅暴露最小运行/证据读取/提案工具，默认无源码写能力；鉴权、输入 Schema、项目绑定、取消/资源限额；固定支持的宿主、SDK、协议与传输版本。
- **验收**：真实客户端互操作；按支持版本分别测试旧版 initialize/capability negotiation 与新版 per-request metadata；未支持版本明确拒绝；会话/重连/取消/畸形包测试；授权记录不由工具调用参数自行抬升。
- **依赖/回滚**：F-05 且确有需求；关闭 MCP 后 CLI/Skill 仍可用。
- **排除**：不把所有版本强制套入旧初始化流程；不采用已弃用 Sampling 作为新 Judge 核心；不替宿主获取登录凭证。版本核对见[研究资料](../research/agent-evolution.md)。

<a id="s-03"></a>

## S-03 · 版本化经验库和加载器

- **依据/范围**：当前 improvement 输出建议/草稿，不存在受管理经验→下一轮加载的可靠链。新增独立经验存储与加载端口，不直接写用户全局系统指令。
- **交付**：proposed/validated/active/expired/revoked 状态；来源、适用范围、内容哈希、反例、TTL/失效依据；检索、去重、冲突、上下文预算、敏感数据和注入检查。
- **验收**：下一轮运行记录实际加载的经验版本；未激活/过期/跨项目经验不进入上下文；恶意工具输出不能提升为系统规则；清除活动引用可恢复原基线；经验更新不修改项目源码。
- **依赖/回滚**：Q-03/04、F-04；版本化激活指针，旧版本可保留审计但不自动加载。
- **排除**：保存所有对话原文作为无限记忆、训练基础模型权重。

<a id="s-04"></a>

## S-04 · 人工驱动的软进化端到端试验

- **依据/范围**：组合现有评估能力和新经验加载器，增加有限候选试验与显式激活，不先做常驻循环。
- **交付**：一个有已知失败的可重复样例；固定基线/数据/策略→经验候选→独立回归/保留集→人工确认→下一轮加载→回退。
- **验收**：展示质量改善和一个负面候选被拒；全程项目源码不变；缺必需 Judge/缺结果不能激活；预算/授权/提案证据齐全；单靠 accepted/verified 字段无法跳过验证。
- **依赖/回滚**：S-01/03、Q-04、F-05；执行未知候选代码必须使用 H-01 边界；人工样例不能被宣传为安全自动模式。
- **排除**：持续触发、自动硬模式、远端发布。
