# 后续实施工作协议

## 每个任务的开始条件

1. 从[总表](README.md)选择一个 ID，重新检查当前源码和 Git 状态；本轮审计不是永久事实。
2. 说明目标、非目标、可改路径、兼容边界、验收命令和停止条件。
3. 不覆盖用户已有修改；未知文件和旧实验先分类，不清空工作区。
4. 更新任务状态需要实际实现及验证证据。文档草案、类型存在或测试数量增加都不等于功能完成。

## 交付格式

每个任务记录：基线 commit / 环境 → 变更路径 → 行为变化 → 测试结果 → 未覆盖边界 → 回滚方案 → 对应文档更新。实现者可以新建该任务的短执行记录，但不要复制整份目标文档作为第二套规范。

对代码进行机械重构时保持输出和公共 API 兼容；有意修复行为（例如缺失 Judge 不再通过）单独说明迁移影响并添加失败用例。代码规范、安全规范、目标质量和用户授权是不同维度。

## 默认验证

从安装完依赖的仓库运行 `pnpm build`、相关包测试，再视改动运行 `pnpm test`、`pnpm typecheck`、`pnpm lint`、`pnpm demo:headless`、`pnpm format:check`。覆盖率改动必须运行 fixture；跨平台和宿主行为需要真实集成证据，不用单元测试代替。

测试失败必须分类为本次回归/旧问题/环境问题并保留输出，不修改门槛以制造通过。对自动写能力，还必须完成[POL 规则](../design/evolution-policy.md)的拒绝测试。

## 任务结束与回滚

- 完成：交付物、验收和文档均已落实，未实现内容仍标待实施。
- 阻塞：记录实际依赖和缺失输入，不擅自扩大范围。
- 回滚：优先撤回本任务独立变更；涉及产物格式时保证旧数据可读，不能靠删除用户历史恢复。
- 本次文档重构没有授权未来 Agent 直接启动上述开发、调用付费模型或修改目标项目。
