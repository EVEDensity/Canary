# R10：统一项目结构与变更模型

本阶段将架构地图、覆盖联动和 CI 诊断共用的数据结构落地。实现与操作契约见[结构指南](../guides/project-structure.md)，验收范围见[执行记录](../evidence/r10-execution.md)。

| 工作                                          | 状态与边界                                                                        |
| --------------------------------------------- | --------------------------------------------------------------------------------- |
| workspace、应用、包、目录、文件、函数、类节点 | 已实现；JS/TS 符号与可用 Python AST，Go/Rust 目前只到包和文件                     |
| 模块导入、包依赖、可靠调用关系                | 已实现静态可解析关系；动态或跨语言调用标记未知                                    |
| 用户定义架构分层                              | `canary.architecture.json` v1，显式路径规则                                       |
| Git baseline 与工作树增删改重命名             | `--base` 显式选择提交；不确定移动保持增删                                         |
| 稳定节点身份与历史运行关联                    | 路径/符号稳定 ID、源码位置和 SHA-256、提交及运行 manifest；重命名通过前后 ID 关联 |
| 页面、CLI、覆盖与 AI 共用                     | 页面 API、`canary structure`、覆盖哈希链接、只读 MCP 工具读取同一运行快照         |

本阶段交付结构数据与可读诊断，不包含三维布局、交互地图、运行时调用追踪或跨语言精确调用图。后续可视化必须直接消费已封存的结构，不能用现行源码解释历史运行。
